# `preprocessing/` — Book Preprocessing Pipeline

Runs **once per book** (or when you want to reprocess). Takes a raw PDF textbook and produces structured data that the router and generator consume at query time.

## Pipeline Stages

```
PDF ──► extract_toc ──► split_sections ──► extract_images ──► build_index
         │                │                  │                  │
         ▼                ▼                  ▼                  ▼
       TOC entries    Section JSONs      Images/diagrams    index.json
                      (with hierarchy)   + equations        + confusable_pairs.json
```

## Module Overview

| Module | Purpose |
|--------|---------|
| [`run_pipeline.py`](run_pipeline.py) | Orchestrator — runs all 4 stages in sequence |
| [`extract_toc.py`](extract_toc.py) | Extracts table of contents from PDF (bookmarks + font analysis) |
| [`split_sections.py`](split_sections.py) | Splits PDF into section-level JSON files with hierarchy |
| [`extract_images.py`](extract_images.py) | Extracts raster images, vector diagrams, and equations |
| [`build_index.py`](build_index.py) | Builds hierarchical TF-IDF index with optional LLM abstracts |

## Usage

```bash
cd Phase-0

# Process a single book
python -m preprocessing.run_pipeline books/raw/fluid_mechanics.pdf

# Process all PDFs in books/raw/
python -m preprocessing.run_pipeline

# Force reprocessing
python -m preprocessing.run_pipeline books/raw/fluid_mechanics.pdf --force
```

## Output Structure

After processing, each book gets a directory under `books/processed/`:

```
books/processed/fluid_mechanics/
├── sections/                    # Per-section JSON files
│   ├── 1-introduction.json
│   ├── 2-1-fluid-statics.json
│   └── ...
├── images/                      # Extracted visuals
│   ├── raster/
│   ├── diagrams/
│   └── equations/
├── index.json                   # Hierarchical index (router input)
├── confusable_pairs.json        # Sibling sections with >60% keyword overlap
├── qa_report.txt                # Section length outlier warnings
└── test_questions.json          # Hand-written eval questions (Phase 1)
```

### `index.json` Structure

```json
{
    "book_name": "Fluid Mechanics",
    "total_sections": 45,
    "chapters": [
        {
            "section_id": "1",
            "title": "Introduction",
            "level": 1,
            "keywords": ["fluid", "mechanics", ...],
            "tfidf_keywords": ["viscosity", "newtonian", ...],
            "abstract": "Introduces fundamental concepts...",
            "has_visuals": true,
            "children": [
                {
                    "section_id": "1.1",
                    "title": "What is a Fluid?",
                    ...
                }
            ]
        }
    ]
}
```

### `confusable_pairs.json` Structure

```json
[
    {
        "section_a": "3.2",
        "section_b": "3.3",
        "overlap": 0.72,
        "shared_keywords": ["pressure", "force", "equilibrium"]
    }
]
```

## Key Design Decisions

### Hierarchical Sections
Each section stores `parent_id` and `children`, enabling the router's two-stage approach (chapter → section). The tree structure mirrors the book's actual TOC.

### TF-IDF Keywords
Corpus-aware keyword extraction. Common words like "algorithm" get down-weighted, while locally unique terms get boosted. Used by:
- The router's LLM prompts (Stage 2 context)
- The keyword fallback scorer (non-LLM backup)

### LLM Abstracts
Optional (set `LLM_ABSTRACTS_ENABLED=true`). When enabled, each section gets a rich semantic description generated by the LLM at build time. Falls back to first-2-sentence extraction when disabled.

### `build_index.py` uses `core.llm_client`
The LLM calling logic was extracted into `core/llm_client.py` to avoid duplication with the router and generator modules.
